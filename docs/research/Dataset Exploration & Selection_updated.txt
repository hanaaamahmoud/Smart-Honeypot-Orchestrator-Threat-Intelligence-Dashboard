# Dataset Exploration & Selection
## Smart Honeypot Orchestrator & Threat Intelligence Dashboard

---

## Overview

This document summarizes the dataset 
evaluation process conducted for the 
project. Over 40 public honeypot datasets 
were reviewed across GitHub, Kaggle, 
and Zenodo. Datasets were assessed based 
on the following criteria:

- Real honeypot deployment (not synthetic)
- Public IP addresses (for GeoIP enrichment)
- Application-layer data (not network flows)
- Sufficient volume for ML clustering
- Relevant protocols (SSH, HTTP, FTP)

---

## Evaluation Criteria

| Criterion | Description |
|-----------|-------------|
| Real Honeypot | Data collected from internet-facing honeypot |
| Public IPs | Real attacker IPs (not hashed/anonymized) |
| Application Layer | Session-level data (credentials, commands, paths) |
| Volume | Minimum 500+ unique IPs for clustering |
| Protocol Coverage | SSH, HTTP, or FTP data |

### 1. SSH - MURHCAD
**Source:** Zenodo (Open Access)
**Honeypot:** Cowrie (Medium-Interaction)
**Period:** 3 months
**Volume:** 92,929 events | 7,945 sessions

**Why Selected:**
- Real internet-facing Cowrie deployment
- Rich application-layer features
- Full GeoIP enrichment included
- Credentials + commands + session data
- HASSH network fingerprinting

**Key Features Available:**
src_ip, timestamp, session_id
username, password
commands executed per session
session duration
file download attempts
GeoIP (country, city, ASN)
HASSH fingerprint

## 2. HTTP Dataset — SNARE/TANNER

**Source:** Public GitHub Repository
**Honeypot:** SNARE/TANNER (Medium-Interaction)
**Format:** JSONL (tanner_report.json.*)
**Volume:** 2,522 records | 549 unique IPs
**Files:** 29 log files

**Why Selected:**
- Real medium-interaction HTTP honeypot
- Rich attack payloads captured
- POST body data available
- User-agent strings present
- Real attack paths:
  - /muhstik.php (Muhstik Botnet)
  - /vendor/phpunit/.../eval-stdin.php (PHP RCE)
  - /HNAP1/ (Router Attack)
  - /.env, /.git (Reconnaissance)

**Key Features:**
ip (attacker), timestamp
request path, HTTP method
user-agent string
post_data (attack payloads)
attack_type (labeled):

RCE (404 records)
AdminProbe (154 records)
Recon (51 records)
Webshell (40 records)
Normal (1,873 records)

#### 5.3 MURHCAD Dionaea (FTP)
**Volume:** 344 FTP records | 93 unique IPs
**Problem:**
- Most arguments = anonymous/TLS only
- Only 1 real credential found
  ('server', '1q2w3e4r')
- Anonymous FTP ≠ brute-force attacks
- Not suitable for behavioral ML

#### 5.4 CICHoneynet2023
**Volume:** 272 FTP packets | 21 unique IPs
**Problem:**
- Anonymous FTP access only
  (USER anonymous, PASS anonymous@)
- Not brute-force behavior
- Private honeypot IP (192.168.10.111)

#### 5.5 CUIP-X25 (FTP)
**Volume:** 7,090 FTP rows
**Problem:**
- login_username = 0.0 (empty, pipeline bug)
- login_password = 0.0 (empty, pipeline bug)
- Attack types = Port Scanning only
- No application-layer credentials

#### 5.6 Other Evaluated Datasets
All other evaluated datasets either:
- Contained no FTP data
- Were network-level only (no credentials)
- Were synthetic/lab-generated
- Had insufficient records (<100)

### Root Cause Analysis
Why is FTP data scarce publicly?

FTP honeypots capture less traffic compared to SSH/HTTP
Most operators don't publish raw FTP credential logs (privacy)
Dionaea focuses on malware downloads, not credential capture
Heralding is the best FTP honeypot but deployed data is not public

### Current Status
After evaluating 40+ public datasets,
no suitable FTP honeypot dataset was
found with:
Real public IPs
Application-layer credentials
Sufficient volume (>500 sessions)
Brute-force behavior patterns

## Additional Services Evaluated

The following services were explored as 
potential alternatives, particularly 
for replacing FTP:

| Service | Dataset Found | Rejection Reason |
|---------|--------------|-----------------|
| MSSQL | Dionaea SQLite (865K logins) | Database service, not IT service. Feature space incompatible with SSH/HTTP when combined in unified ML model. Outside project scope |
| SMB | Dionaea SQLite (369K connections) | Exploit-based (EternalBlue), no credentials captured, not suitable for behavioral clustering |
| MySQL | Dionaea SQLite (2,240 logins) | Same limitation as MSSQL - database protocol outside IT service scope |
| VNC | Heralding (1M+ records) | Remote desktop protocol, low-interaction only, outside SSH/HTTP/FTP scope |

**Note on MSSQL:**
Although MSSQL data showed excellent 
clustering results (Silhouette = 0.805)
and rich attack behavior including 
APT-level command chains, it was 
excluded because:
1. Database protocol ≠ IT service
   (SSH/HTTP/FTP are IT services)
2. Feature space incompatibility when
   merging with SSH/HTTP in a unified
   ML model
3. Outside defined project scope
