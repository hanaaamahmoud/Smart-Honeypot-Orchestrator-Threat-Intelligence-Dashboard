# Step 7 — Behavioral Analysis

## 1. Overview
This step focused on analyzing the behavioral clusters generated in Step 6.
The main objectives were to:

* Profile the discovered clusters.
* Compare clustering results across different algorithms.
* Select the primary behavioral model.
* Assign human-readable behavioral labels.
* Build a reusable behavioral reference.
* Validate the stability of the selected clustering model.

The analysis covered five stages:

**7A (Cluster Profiling)** → **7B (Cross-Model Comparison)** → **7C (Model Selection & Behavioral Labeling)** → **7D (Detailed DBSCAN Profiling)** → **7E (Cluster Validation)**

---

## 2. Step 7A — Cluster Profiling
The first stage analyzed the clusters generated by K-Means, DBSCAN, and Agglomerative Clustering.

### Data Verification
The source behavioral dataset was verified using:

* **SHA-256 integrity checking**
* **Session count validation**
* **`reconstructed_session_id` uniqueness and missing-value checks**

### Label Leakage Detection
Forbidden supervised labels were excluded from the behavioral analysis, including:

* `attack_type`
* `attack_stage`
* `severity`
* `mitre_technique`
* `label`

### Cluster Integration
The cluster assignments from Step 6 were loaded and matched with the behavioral session data using `reconstructed_session_id`. The three clustering results were then combined into a unified dataset.

### Global Feature Statistics
Statistical measurements were calculated for the behavioral features, including: Mean, Standard Deviation, Median, Minimum, Maximum, and IQR. The results were saved as:
`step7a_global_feature_statistics.csv`

### Cluster Behavioral Profiles
For each clustering algorithm, cluster sizes and behavioral statistics were calculated, including:

* Number of sessions per cluster.
* Percentage of total sessions.
* Mean behavioral feature values.
* Median behavioral feature values.
* Standard deviation.

### Discriminating Features
The most important behavioral differences between each cluster and the global dataset were identified using Z-Scores:

$$Z = \frac{\mu_{\text{cluster}} - \mu_{\text{global}}}{\sigma_{\text{global}}}$$

The top discriminating features were exported for each model.

> **Result:** Step 7A produced detailed behavioral profiles that describe how each cluster differs from the overall session population.

---

## 3. Step 7B — Cross-Model Comparison
This stage compared the behavioral results produced by the three clustering algorithms.

### Feature Validation
A strict behavioral feature filter was applied to ensure that:

* Cluster assignment columns were excluded.
* IDs and timestamps were excluded.
* Only direct behavioral features were used.
* Missing and invalid features were checked.

### Cross-Model Feature Overlap
The top discriminating features from each model were compared. The similarity between models was measured using the **Jaccard Similarity Index**:

$$J(A,B) = \frac{|A \cap B|}{|A \cup B|}$$

This helped identify behavioral features that were consistently important across different clustering algorithms.

### Structural Comparison
The models were also compared based on their cluster structure, including:

* Cluster sizes.
* Largest and smallest clusters.
* Cluster distribution.
* DBSCAN noise behavior.

The comparison and audit results were saved as: `step7b_corrected_audit.json`

> **Result:** This stage showed how consistently the different clustering algorithms identified similar behavioral patterns.

---

## 4. Step 7C — Model Selection & Behavioral Labeling
This stage selected the primary clustering model and assigned descriptive behavioral labels.

### Model Selection
The clustering results from Step 6 were evaluated together with their behavioral characteristics. The selected model hierarchy was:

* **Primary Model:** DBSCAN
* **Secondary Model:** Agglomerative Clustering
* **Baseline Model:** K-Means

DBSCAN was selected as the primary model because its density-based approach can identify behavioral groups while also isolating unusual sessions as noise.

### Behavioral Labeling
Clusters were assigned descriptive behavioral names instead of predefined attack labels. Examples include:

* *Dominant Baseline Behavior*
* *Dense Recurrent Behavioral Pattern*
* *DBSCAN Noise / Isolated Behavior*

These labels describe observed behavioral patterns rather than claiming a specific attack type.

### Final Session Assignments
A behavioral label was assigned to all **11,880** sessions. The final assignments were exported as:
`session_behavioral_cluster_assignments.csv`

The model selection audit was saved as:
`step7c_model_selection_audit.json`

> **Result:** This stage transformed numerical cluster IDs into understandable behavioral categories while maintaining the unsupervised nature of the analysis.

---

## 5. Step 7D — Detailed DBSCAN Behavioral Profiling
Since DBSCAN was selected as the primary model, this stage created a detailed behavioral reference for the DBSCAN clusters.

### Global Behavioral Reference
The overall statistical behavior of the session population was calculated for the behavioral features. This provided a baseline for comparing individual DBSCAN clusters.

### Cluster Behavioral Signatures
Each DBSCAN cluster was analyzed using:

* Cluster size.
* Feature statistics.
* Z-Score deviations.
* Top discriminating behavioral features.

The DBSCAN noise cluster (`-1`) was analyzed separately to identify isolated or unusual behavioral patterns.

### Reusable Behavioral Reference
The complete DBSCAN behavioral reference was packaged into:
`step7d_behavioral_reference.json`

This artifact provides a reusable reference for future behavioral analysis and comparison. A final integrity and audit report was also generated:
`step7d_detailed_behavioral_profiling_audit.json`

> **Result:** Step 7D created a structured behavioral reference describing the normal and unusual patterns discovered by the selected DBSCAN model.

---

## 6. Step 7E — Cluster Validation & Stability Check
The final stage evaluated the stability and consistency of the DBSCAN clustering results.

### Baseline Evaluation
The selected clustering was evaluated using:

* **Silhouette Score**
* **Davies-Bouldin Index**
* **Calinski-Harabasz Index**

Missing values were handled using median imputation where required.

### Stability Testing
To test whether the discovered clusters remained consistent under changes in the input data:

1. Random samples containing 80% of the sessions were created.
2. Five different random seeds were used.
3. DBSCAN was re-run using the same parameters.
4. The resulting clusters were compared with the original clustering.

Cluster consistency was measured using:

* **Adjusted Rand Index (ARI)**
* **Adjusted Mutual Information (AMI)**

> **Result:** The resampling analysis provided an estimate of how stable the DBSCAN behavioral structure was under different samples of the dataset. The final validation report was saved as `step7e_cluster_validation_audit.json`.

## 8. Result
Step 7 transformed the raw clustering outputs from Step 6 into an interpretable behavioral analysis framework. 

The process:

**Cluster Profiling** → **Cross-Model Comparison** → **Model Selection** → **Behavioral Labeling** → **DBSCAN Reference** → **Stability Validation**

resulted in a reusable behavioral reference based on unsupervised session behavior, without relying on predefined attack labels. 

The selected DBSCAN model and its behavioral reference provide the foundation for the next stage:

**Dashboard / Session Replay** → **Threat Analysis** → **Productionization**
